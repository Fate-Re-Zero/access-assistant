# Real Info Limit Skill

解决实名认证、操作上限增加次数问题。

## 工具说明

### MCP 工具

| 工具名 | 必填参数 |
|--------|---------|
| `auth-mcp-server_sqg_real_info_risk_limit_clear` | `account` |

**使用原则：**

1. **仅**调用 `sqg_real_info_risk_limit_clear`
2. 从问题中提取用户账号或手机号传入参数`account`

## 工作流程

1. **接收输入** - 用户问题描述
2. **提取参数** - 从问题提取用户账号或手机号等参数信息
3. **调用MCP工具** - 调用auth-mcp-server_sqg_real_info_risk_limit_clear工具
4. **结论输出** - 整合MCP工具的返回结果，给出明确结论与建议
5. **失败重试** - 若处理失败，从步骤 2 起**整体流程**重试，**最多重试 2 次**（见下节）

## 失败与整体流程重试

**视为处理失败**（尚未给出基于MCP工具的有效结论）：

- 未调用当前问题类型**应当**调用的MCP工具
- MCP工具调用报错、超时或无有效返回
- 工具链异常导致无法按 SKILL 格式输出（非用户刻意缺参）

**重试策略：**

1. 从**整体流程**重头执行：提取参数 → 调用MCP工具 → 结论输出
2. **最多重试 2 次**（首次处理 + 最多 2 次重试，共最多 **3 轮**完整流程）
3. 3 轮仍失败：明确告知「当前认证工具存在异常，无法完成排查，请联系相关业务开发」；**禁止**凭猜测作答

**重试时禁止：**

- 在同一轮流程内对**同一MCP工具相同参数**反复调用
- 超过 2 次整体流程重试后仍继续重试
- 跳过重试直接输出「像是 / 可能是」类结论

## 回复格式

**仅 2 个一级标题：**

```markdown
## 结论
…

## 下一步建议
…
```

**下一步建议：**
- 只写用户**现在**应做的 1–2 条操作（如请让玩家重新进行实名认证或人脸登记操作。）
- **禁止**假设后续情况：不要写「若仍失败请补充…」「如果用户当前仍反馈失败…」「后续如需继续排查/深挖…」
- 仅在**不补充某项信息就无法执行建议**时，用 1 条 bullet 说明需补充什么；不要列一长串可选排查材料

**下一步建议写法（real_info_limit）：**

- 清理成功：已经给用户增加实名认证上限次数，请让玩家重试。若当前页面未更新，先退出后重新进入再尝试。
- 清理失败：说明失败原因，告知需补充的账号/手机号信息或联系人工

**禁止示例（不要这样写）：**
```markdown
## 下一步建议
- …
- 如果用户当前仍反馈失败，请补充失败时间、截图、客户端版本…
```

### 实名认证、操作上限次数回复（real_info_limit）：

```markdown
## 结论
（直接说明 sqg_real_info_risk_limit_clear 增加实名认证次数是否成功、针对的账号/手机号、MCP 返回要点，不需要让用户知道结论是通过MCP工具调用所得，所以不要出现工具返回结果显示这类描述）

## 下一步建议
…
```

## 处理案例

#### 案例 1：实名认证/操作次数达到上限（real_info_limit）

用户问题：

```
账号13932571986  实名认证次数操作上限   想要增加次数
```

或：

```
18877179115  操作上限 增加次数
```

Agent 处理步骤：

1. 调用 `auth-mcp-server_sqg_real_info_risk_limit_clear`，参数示例：

   ```json
   {"account": "18651292881"}
   ```

2. 按「回复格式」**两栏**输出（结论含清理结果 → 下一步建议）

## 注意事项
- 使用中文回复用户
- 一定不能带有猜测性的内容（比如：像是 xxx、可能是 xxx）
- 账号信息不足时，明确告知用户需要补充账号或手机号等关键信息
